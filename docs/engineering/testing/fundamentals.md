# 測試基礎概念

## 測試金字塔

```
                    ╱▔▔▔▔▔▔▔╲
                   ╱  E2E 測試  ╲      ← 少量、慢、貴
                  ╱  (端對端測試)  ╲       Selenium / Playwright
                 ╱─────────────────╲
                ╱    整合測試         ╲   ← 中量、較慢
               ╱  (Integration Test)  ╲    @SpringBootTest
              ╱                         ╲   Testcontainers
             ╱─────────────────────────╲
            ╱          單元測試           ╲ ← 大量、快、便宜
           ╱        (Unit Test)           ╲  JUnit 5 + Mockito
          ╱▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁╲

測試比例（建議）：
  單元測試    70%  → 快速、隔離、大量
  整合測試    20%  → 驗證組件間協作
  E2E 測試    10%  → 驗證核心用戶流程

原則：
  越往上層 → 越慢、越貴、越脆弱（環境問題）
  越往下層 → 越快、越穩定、越易於定位問題
```

## FIRST 原則（好測試的標準）

```
F - Fast（快速）
    單元測試應該在毫秒內執行
    整個測試套件應該在幾分鐘內完成

I - Independent（獨立）
    測試之間不相互依賴
    每個測試可以單獨執行（順序無關）
    ❌ TestB 依賴 TestA 的執行結果

R - Repeatable（可重複）
    在任何環境下結果一致
    不依賴外部狀態（日期、網路、隨機數）
    ❌ 今天通過，明天因為日期不同而失敗

S - Self-validating（自驗證）
    測試結果只有通過或失敗，不需要人工判斷
    ❌ 需要人工查看日誌來判斷是否正確

T - Timely（及時）
    TDD：在生產程式碼之前寫測試
    最遲在功能完成時同步寫測試
    ❌ 等所有功能都完成後才補測試（往往來不及）
```
